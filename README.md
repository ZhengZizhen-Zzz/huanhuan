# 缓缓 Huanhuan

**一款面向压力和无聊嘴馋场景的轻量互动产品：用一次短互动，给想吃的念头留一点缓冲；用日历印章和贴纸收藏，留下每一次尝试。**

知道自己未必饿，却还是反复翻外卖、找零食。缓缓选择在“想吃”到“下单或拿起食物”之间提供帮助：选一个当下能做的小动作，再决定接下来怎么做。

当前已完成可交互 Web 原型，面向小程序体验设计。手机和电脑均可直接打开。

**项目时间：2026 年 9 月集中打磨约一个月，10 月继续调研、迭代与公开整理。**

![当前版本的首页、日历与收藏](preview.png)

## 核心体验

| 模块 | 用户可以做什么 | 设计目的 |
| --- | --- | --- |
| **缓一缓** | 选择饿了、嘴馋或心情不好；输入想吃的食物，也可直接开始收纳、砸碎或节奏呼吸 | 降低开始行动的门槛，让不同状态有不同出口 |
| **日历** | 按周、按月回看记录；确认一天的健康饮食章，查看暂时不吃的累计次数 | 让单次尝试可回看，形成持续积累 |
| **收藏** | 完成互动获得贴纸，在收藏袋里查看；保存自己想看到的提醒文字 | 给完成行动一个即时反馈，提供再次打开的理由 |

```text
打开缓缓 → 选择状态（可跳过）→ 选择食物（可跳过）
                    ↓
        做一次互动：收纳 / 砸碎 / 呼吸
                    ↓
        记录结果：暂时不吃 / 吃了 / 还没决定
                    ↓
             日历记录 + 贴纸积累
```

选择“饿了”会进入进食建议；首页食物贴纸也可直接开启互动。一次暂时不吃计入次数，全天健康饮食章则由用户另行确认。[查看完整交互与数据规则 →](PRD.md)

## 为什么这样设计

三轮小红书公开内容调研阅读了 **72 篇去重帖子详情**，用于发现需求线索和反例。它们是公开内容研究，不是用户访谈或效果验证。

| 需求线索 | 当前选择 | 仍需验证 |
| --- | --- | --- |
| 想吃时未必愿意分析原因，也不一定手边有食物照片 | 状态与食物输入可跳过，贴纸可以直接进入互动 | 简化入口是否让更多人完成一次使用 |
| 压力想吃与无聊嘴馋需要不同回应 | 保留状态分流和可切换动作，饥饿有独立出口 | 动作是否适合当下，而不只是好玩 |
| 有人期待累计反馈，也有人嫌记录麻烦、只记理想结果 | 互动后轻量记录，三种结果都可保存；单次次数与每日章分开 | 是否愿意真实记录，并在下一次需要时回来 |
| 模拟点单有吸引力，也出现“玩完仍想下单”的反例 | 保留在需求池，首版先验证短互动 | 更强的食物刺激是否反而延长纠结 |

## 与相近产品相比

Eat Right Now 已提供食欲冲动时的练习，AteMate 有餐前提问与快捷记录，Finch 将行动和养成奖励相连，薄荷健康覆盖饮食与体重管理。缓缓选择将**无照片也能开始的食物互动、当次结果与日历收藏**连成一条体验，优先服务“还没吃，但已经很想吃”的时刻。

当前优势是入口轻、动作具体、反馈围绕一次尝试；快捷触达、长期内容和真实效果仍需继续完善。[查看四款产品的流程、差异与取舍 →](COMPETITIVE-ANALYSIS.md)

## 接下来先验证什么

**最大的未知，是用户在想吃的时候会不会打开它。** 下一轮计划招募 6—8 位成年参与者，先回顾最近一次真实经历，再观察无讲解使用，最后开展七日自愿试用。

优先回答三个问题：

1. 在真实想吃的时刻，什么让用户打开，又是什么让用户直接去买？
2. 哪种互动能带来一点决定空间，哪些步骤多余？
3. 日历和收藏让人回来寻求帮助，还是仅仅回来盖章？

若入口不成立，先调整触达和开始路径；若只有新鲜感，先调整互动内容。通知、更多玩法和 AI 建议的开发顺序，由这些结果决定。[验证方法与指标口径 →](VALIDATION.md)

## 一段迭代记录

早期版本想用更多贴纸和说明让页面有趣，实际却让主动作变得不明显。后来的调整是让食物贴纸本身可以操作，再逐步收起不必首屏展示的信息。六版都保留了下来，方便对照这些取舍，而不只看最终截图。
